## 1. Goal

Build a Terraform custom provider for **ZenTao** (self-hosted open-source plus Pro / Biz / Max commercial editions — same PHP REST API surface), following the established `terraform-provider-st-*` template used across all myklst providers.

**MVP scope:** project skeleton + one fully-working resource (`st-zentao_product`) end-to-end (CRUD + import + acceptance tests + generated docs). Four additional resources (`project`, `execution`, `user`, `group`) are planned but deferred to future iterations.

**Non-goals:**
- ZenTao Cloud / multi-tenant SaaS (`zentao.net`) — different host model, deferred.
- Flowing work items (story / task / bug / testcase) — these belong in the ZenTao UI, not Terraform state.
- Datasource resources — deferred to a follow-up after the resource layer stabilises.
- Rate limiting (no evidence self-hosted ZenTao needs it; YAGNI).

## 4. Components

### 4.1 `main.go`

Identical pattern to all myklst providers:

```go
func main() {
    addr := os.Getenv("PROVIDER_LOCAL_PATH")
    if addr == "" {
        addr = "registry.terraform.io/myklst/st-zentao"
    }
    providerserver.Serve(context.Background(), zentao.New, providerserver.ServeOpts{
        Address: addr,
    })
}
```

Plus `//go:generate go run github.com/hashicorp/terraform-plugin-docs/cmd/tfplugindocs generate --provider-name st-zentao`.

### 4.2 `zentao/provider.go`

Implements `provider.Provider`. Schema:

| Field | Type | Required | Sensitive | Env fallback |
|---|---|---|---|---|
| `url` | String | yes | no | — |
| `account` | String | optional | yes | `ZENTAO_ACCOUNT` |
| `password` | String | optional | yes | `ZENTAO_PASSWORD` |

`Configure`:
1. Merge `req.Config` with env vars (config wins when set).
2. Fail-fast `AddError` if any of `url` / `account` / `password` empty after merge.
3. Build `Config{...}.Client()`. If client init (which performs first Login) fails → `AddError` with reason; subsequent resources will not run.
4. `resp.ResourceData = client`, `resp.DataSourceData = client`.

`Resources()` returns `[NewProductResource]`. `DataSources()` returns empty for MVP.

### 4.3 `zentao/config.go`

```go
type Config struct {
    URL      string
    Account  string
    Password string
}

func (c *Config) Client() (*zentaoapi.Client, error) {
    return zentaoapi.NewClient(c.URL, c.Account, c.Password)
}
```

### 4.4 `zentaoAPI/client.go`

```go
type Client struct {
    baseURL   *url.URL
    account   string
    password  string

    sessionMu sync.Mutex   // protects sessionID; serialises refreshes
    sessionID string

    http      *http.Client
}

func NewClient(rawURL, account, password string) (*Client, error) {
    // parse URL, init http.Client with sane timeouts (30s),
    // call Login() once, return error if Login fails.
}

func (c *Client) doRequest(ctx context.Context, method, path string, query url.Values, body any) ([]byte, error) {
    // 1. wrap with backoff for transient network/5xx errors (MaxElapsedTime = 2min)
    // 2. attach ?zentaosid=<sid> using current sessionID
    // 3. on response: if isSessionExpired(resp), call refreshSession(); replay request ONCE
    // 4. return raw body for endpoint-specific unmarshalling
}
```

Key constraints:
- Session-refresh is independent from network-backoff — 401/"please login" does **not** trigger backoff.
- Replay is bounded to 1 attempt to prevent infinite loops if credentials are revoked.
- `ctx` cancellation is honoured at every layer.

### 4.5 `zentaoAPI/auth.go`

- `Login(ctx)`: POST `/api.php?m=user&f=apilogin` with `account` + `password`. Parses sessionID from envelope, stores under `sessionMu`.
- `refreshSession(ctx)`: takes `sessionMu`, double-checks current sessionID against the one observed before the 401 (if changed, another goroutine refreshed already — return), else calls `Login`.
- `isSessionExpired(httpStatus int, body []byte) bool`: returns true on `401`, **or** on HTTP 200 with body `{"status":"failed", "reason":"please login"}` (ZenTao's actual session-expiry response).

### 4.6 `zentaoAPI/types.go`

```go
type ZentaoResponse struct {
    Status string          `json:"status"`            // "success" | "failed"
    Reason string          `json:"reason,omitempty"`
    Data   json.RawMessage `json:"data,omitempty"`    // sometimes object, sometimes string-encoded JSON
}

var (
    ErrNotFound       = errors.New("zentao: resource not found")
    ErrUnauthorized   = errors.New("zentao: invalid credentials")
)

type APIError struct {
    HTTPStatus    int
    ZentaoStatus  string
    Reason        string
    RawBody       []byte
}

func (e *APIError) Error() string { /* redacts password if echoed */ }
```

Helper `decodeData(env ZentaoResponse, target any) error` handles both data shapes: if `Data[0] == '"'`, unquote string then unmarshal; else direct unmarshal.

### 4.7 `zentaoAPI/product.go`

```go
type Product struct {

    Name        string `json:"name"`

```

## 5. Data Flow

### 5.1 Session lifecycle

```
Provider.Configure
  └─> config.Client()
       └─> NewClient(url, account, password)
            └─> Login()
                 POST /api.php?m=user&f=apilogin  body: {account, password}
                 resp: {status:"success", data:"{sessionID:'abc', ...}"}
                 └─> client.sessionID = "abc"
```

Per-request flow:

```
Resource CRUD
  └─> client.<EntityOp>(ctx, args)
       └─> client.doRequest(method, path, query, body)
            ├─> http.Do() → 200 OK         → return body
            ├─> http.Do() → 5xx/timeout    → backoff retry (≤ 2min total)
            └─> isSessionExpired(resp)     → true
                 └─> sessionMu.Lock()
                      ├─> double-check sessionID (skip Login if already refreshed)
                      └─> Login() to obtain new sessionID
                 └─> replay request ONCE with new sessionID
                      └─> still expired → APIError("session refresh exhausted")
```

Concurrency guarantee: N concurrent requests hitting 401 simultaneously perform exactly **one** Login (mutex + double-check).

### 5.2 Resource Product CRUD

| TF action | resource_product method | API call | Notes |
|---|---|---|---|
| Create | `Create` | POST `/api.php?m=product&f=create` | Write returned `id` + computed fields back to state. If response `data` is empty, follow with a Get to populate computed fields. |
| Read | `Read` | GET `/api.php?m=product&f=view&productID=<id>` | `ErrNotFound` → `resp.State.RemoveResource(ctx)` |
| Update | `Update` | POST `/api.php?m=product&f=edit&productID=<id>` | ZenTao API has no PATCH; send full updatable payload |
| Delete | `Delete` | GET `/api.php?m=product&f=delete&productID=<id>&confirm=yes` | `ErrNotFound` → success (idempotent) |
| Import | `ImportState` | (no API; passthrough into `id`) | Triggers a subsequent Read |

### 5.3 Known ZenTao API quirks (designed-around)

1. **Envelope `data` shape varies** (object vs string-encoded JSON) — handled by `decodeData` helper.
2. **HTTP 200 ≠ business success** — must inspect `status` field in body.
3. **Delete is GET + `confirm=yes`** — deliberately non-RESTful.
4. **Session expiry responds as HTTP 200**, body `{status:"failed", reason:"please login"}` — `isSessionExpired` checks both status code and body.
5. **Some create-time fields are mandatory but undocumented** (e.g. `acl`, `type`) — schema provides defaults to bridge.

## 6. Error Handling

### 6.1 Error taxonomy

| Sentinel / Type | When | Resource-layer reaction |
|---|---|---|
| `ErrNotFound` | GET returns 404 or `status:"failed", reason:"not found"` | `resp.State.RemoveResource(ctx)` (Read) or treat as success (Delete) |
| `ErrSessionExpired` | Internal only; never escapes the client | Triggers refresh + replay |
| `ErrUnauthorized` | Login fails with bad credentials | `AddError` from Configure or operation |
| `ErrValidation` | ZenTao business rule rejection (e.g. duplicate `code`) | `AddError` with original reason |
| `*APIError` | Catch-all with `HTTPStatus`, `ZentaoStatus`, `Reason`, `RawBody` | `AddError` with formatted detail |

Resource code uses `errors.Is` / `errors.As` consistently.

### 6.2 Edge cases (must-handle)

**Session:**
- First Login fails (bad creds) → fail Configure with clear diagnostic.
- First Login fails (network) → backoff retry, then fail Configure.
- Mid-run session expiry → transparent refresh + replay (≤ 1).
- Concurrent N × 401 → mutex + double-check ensures single refresh.
- Credentials revoked mid-run → refresh fails → return `ErrUnauthorized`.
- Refresh succeeds but request still 401 → bounded retry, return `APIError("session refresh exhausted")`.

**Network / retry:**
- 5xx + timeouts → `cenkalti/backoff/v4`, `MaxElapsedTime = 2min`.
- Non-401 4xx → no retry.
- `ctx` cancelled → return `ctx.Err()` immediately.

**Resource:**
- External delete between plan and apply → Read returns `ErrNotFound`; TF replans recreate.
- `code` mutation → `RequiresReplace` triggers destroy + create automatically.
- Create returns `id == 0` → treat as API failure; do **not** persist invalid state.
- Update with single field change → still send full updatable payload (API limitation).
- Idempotent Delete: `ErrNotFound` is success.
- Import with non-numeric ID → schema validation rejects.
- Empty `data` on create → fall back to a follow-up Get to fill computed fields.

**Security:**
- `account` and `password` schema attributes are `Sensitive: true`.
- `APIError.Error()` redacts password if echoed in body.
- `tflog` writes only first 6 chars of sessionID (`abc123***`).

### 6.3 Deliberately not handled (YAGNI)

- ZenTao multilingual error messages (no translation layer).
- URL trailing-slash normalisation (delegated to `url.ResolveReference`).
- Rate limiting (add only if a real instance hits it).
- Cloud (`zentao.net`) tenant subdomains (deferred).

## 7. Testing Strategy

### 7.1 Layers

| Layer | Files | Command | Focus |
|---|---|---|---|
| Unit — API client | `zentaoAPI/*_test.go` | `go test ./zentaoAPI/...` | session refresh, envelope decode, error classification, URL building |
| Unit — Provider/Resource schema | `zentao/provider_test.go` | `go test ./zentao/...` | Schema validation, Configure error paths |
| Acceptance — full lifecycle | `zentao/resource_product_test.go` | `TF_ACC=1 go test ./zentao/...` | real Terraform CRUD + import + drift |

### 7.2 Unit — `zentaoAPI` client (httptest server)

Required test cases:
- Login success → sessionID stored.
- Login failure (bad creds) → `ErrUnauthorized`.
- `doRequest` happy path → sessionID present in URL, body decoded.
- 401-retry → first response is `{status:"failed", reason:"please login"}`; refresh + replay succeeds.
- 401-retry exhausted → second attempt also expired → `APIError("session refresh exhausted")`.
- Concurrent 401s → 10 goroutines hit expired session simultaneously; assert Login called exactly once.
- 5xx backoff → fake server returns 503 twice then 200 → success.
- `data` as string-encoded JSON → `decodeData` returns correct struct.
- `data` as direct object → `decodeData` returns correct struct.
- 404 → `ErrNotFound`.
- Password redaction in `APIError.Error()`.

Coverage target: **≥ 85%** for the `zentaoAPI` package.

### 7.3 Unit — Provider

- Schema rejects missing required `url`.
- Configure precedence: config value wins over env var.
- All credentials missing → diagnostic error.
- Configure when initial Login fails → diagnostic error with cause.

### 7.4 Acceptance — `resource_product`

Environment:
```
TF_ACC=1
ZENTAO_URL=http://localhost:8080
ZENTAO_ACCOUNT=admin
ZENTAO_PASSWORD=...
```

Tests (each uses a unique `code` with timestamp suffix; `CheckDestroy` verifies cleanup):
- `TestAccProductResource_basic` — create → read → update name/description → destroy.
- `TestAccProductResource_requiresReplace` — change `code` → destroy + recreate.
- `TestAccProductResource_import` — create → `terraform import` by ID → state matches.
- `TestAccProductResource_disappears` — create → delete via raw client → next plan shows recreate.
- `TestAccProductResource_invalidCredentials` — wrong password → Configure fails.

### 7.5 Makefile

```makefile
go-test-unit:
	go test -v -cover ./zentao/... ./zentaoAPI/...

go-test-acc:
	TF_ACC=1 gotestsum --format=short-verbose ./...

generate-docs:
	go generate ./...

go-lint:
	golangci-lint run
```

CI runs `go-test-unit` only. Acceptance tests run locally or in a dedicated staging environment.

Provide `examples/docker-compose.yml` (or a README pointer) so contributors can spin up a local ZenTao with one command:

```bash
docker run -d -p 8080:80 -e MYSQL_ROOT_PASSWORD=root easysoft/zentao:latest
```

## 8. Out of Scope (this spec)

The following are intentionally deferred and will get their own specs when prioritised:
- Resources: `project`, `execution`, `user`, `group` (planned but not implemented in v0.1).
- Data sources for any entity.
- Resources for flowing work items (story / task / bug / testcase).
